# MVP 갭 분석 및 구현 현황

## 1. 프로젝트 개요
**HobbyTime**은 취미 클래스 예약 서비스입니다.
현재 상태: **Phase 1 (기반) & Phase 2 (핵심 로직) 대부분 완료.**

## 2. 구현 현황 체크리스트

### ✅ 구현됨 (테스트 준비 완료)
| 기능 | 상태 | 상세 내용 |
| :--- | :--- | :--- |
| **인증 (Authentication)** | ✅ 완료 | Google OAuth, 미들웨어 보호, 사용자 생성 트리거. |
| **클래스 탐색 (Discovery)** | ✅ 완료 | 홈 화면 목록, 지역/카테고리 필터링. |
| **클래스 상세 (Detail)** | ✅ 완료 | 정보 조회, 스튜디오 정보, 동적 라우팅. |
| **예약 로직 (Booking)** | ✅ 완료 | DB 트랜잭션(RPC), 동시성 제어, 좌석 관리. |
| **내 예약 (My Reservations)** | ✅ 완료 | 목록 조회, 상태 뱃지, 취소 기능. |
| **UI/UX** | ✅ 완료 | 반응형 디자인, 토스트 알림, 빈 상태(Empty states), 낙관적 업데이트(취소 시). |

### ⚠️ 지연됨 / 누락됨 (MVP 비필수)
| 기능 | 상태 | 권장 사항 |
| :--- | :--- | :--- |
| **관리자 대시보드** | ⏸️ 지연됨 | 관리자 기능은 우선순위 조정됨. 현재 `/admin`에서 모의 데이터 사용 중. |
| **AI 요약** | ⏸️ 지연됨 | `ClassDetailContent`에서 정적 모의 데이터 사용 중. |
| **페이지네이션** | ❌ 누락됨 | 클래스 목록의 무한 스크롤/페이지네이션 누락. (클래스가 50개 미만인 MVP에서는 수용 가능). |
| **프로필 페이지** | ❌ 누락됨 | 이름/아바타 수정 불가. 기본적인 `UserMenu`만 존재. |

## 3. UX 및 흐름 분석

### 🟢 장점
- **매끄러운 예약**: 예약 흐름이 직관적임 (선택 -> 예약 -> 확정).
- **피드백**: `useTransition`을 활용한 로딩 상태와 토스트 알림이 적절히 배치됨.
- **안전장치**: 서버 측 검증 및 DB 제약 조건으로 중복 예약 방지.

### 🔴 단점 / 어색한 흐름
1.  **예약 후 리다이렉트**:
    - **현재**: 페이지에 머무르거나 미세한 리다이렉트?
    - **개선**: `/my/reservations`로 이동하거나, "내 예약으로 가기" 버튼이 있는 "성공 모달" 띄우기. 현재는 클라이언트에서 `{ success: true }` 처리.
2.  **취소 시 시각적 피드백**:
    - **현재**: 기능은 정상이나 `window.confirm` 사용.
    - **개선**: 네이티브 `confirm` 대신 UI 다이얼로그(Dialog)로 교체하여 더 세련된 느낌 제공.
3.  **로그인 마찰**:
    - **현재**: 예약 중 비로그인 시 로그인 페이지로 이동.
    - **개선**: 로그인 후 다시 예약 페이지로 돌아오도록 처리(Intent 보존). 미들웨어의 `next` 파라미터 처리는 잘 되어 있음.

## 4. 결론
**핵심 MVP 기능은 구현 완료되었습니다.**
사용자는 가입, 클래스 탐색, 예약, 취소를 수행할 수 있습니다.
예외 사항은 관리자 기능(DB 접근 필요)과 AI 기능이며, 이는 MVP 이후로 연기되었습니다.
