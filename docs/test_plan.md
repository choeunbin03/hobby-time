# HobbyTime 테스트 계획서

## 1. 테스트 전략
두 가지 레벨로 애플리케이션을 검증합니다:
1.  **단위/컴포넌트 테스트**: 개별 부품의 동작 확인.
2.  **통합/E2E 테스트 (수동)**: 전체 사용자 여정(User Journey) 검증.

---

## 2. 단위 및 컴포넌트 테스트

### 대상: `utils` 및 핵심 컴포넌트

| 컴포넌트 / 함수 | 테스트 케이스 | 예상 동작 |
| :--- | :--- | :--- |
| **CategoryFilter** | 카테고리 칩 클릭 | URL이 `?category=...`로 변경됨. 활성 스타일 적용됨. |
| **RegionFilter** | 지역 선택 | URL이 `?region=...`로 변경됨. 활성 스타일 적용됨. |
| **ClassCard** | Props 렌더링 | 이미지, 제목, 가격(콤마 포맷), 스튜디오 이름이 표시됨. |
| **ReservationList** | 빈 상태(Empty State) | 목록이 비어있으면 "예약 내역이 없습니다" 표시. |
| **ReservationList** | 취소 액션 | '취소' 클릭 시 확인창 표시 -> 서버 액션 호출. |

### 테스트용 모의 데이터 (Mock Data)
컴포넌트를 격리해서 테스트할 때(예: Storybook) 사용:

```typescript
// mock-class.ts
export const mockClass = {
  id: "test-uuid",
  name: "테스트 요리 클래스",
  category: "요리",
  price: 50000,
  studios: { name: "테스트 스튜디오", location_text: "서울 강남" }
};
```

## 3. 통합 / E2E 테스트 (핵심 사용자 여정)

### 시나리오 A: 신규 사용자 예약 흐름 (Happy Path)
**전제 조건**: 사용자가 로그인하지 않은 상태.

| 단계 | 액션 | 예상 결과 |
| :--- | :--- | :--- |
| 1 | 홈 방문 (`/`) | 클래스 목록 표시됨. 필터 버튼 보임. |
| 2 | 클래스 클릭 | `/classes/[id]`로 이동. 상세 페이지 로드됨. |
| 3 | "예약하기" 클릭 | `/classes/[id]/book`으로 이동. |
| 4 | **로그인 트리거** | 비로그인 상태이므로 구글 로그인으로 리다이렉트 또는 알림. |
| 5 | 로그인 완료 | 예약 페이지(또는 홈)로 다시 돌아옴. |
| 6 | 회차 및 인원 선택 | 회차 선택됨. 가격 업데이트됨. |
| 7 | "예약 확정" 클릭 | 로딩 스피너 표시됨. |
| 8 | **성공** | "예약이 확정되었습니다" 토스트 알림. 내 예약으로 이동/링크 표시. |
| 9 | DB 확인 | `reservations` 테이블에 행 추가됨. `class_sessions.booked_count` 증가함. |

### 시나리오 B: 예약 취소 흐름
**전제 조건**: 확정된 예약이 최소 1개 있음.

| 단계 | 액션 | 예상 결과 |
| :--- | :--- | :--- |
| 1 | 내 예약 방문 | 시나리오 A의 예약이 보임. 상태: **예약 확정**. |
| 2 | "취소" 클릭 | "정말로 취소하시겠습니까?" 확인창 표시. |
| 3 | 취소 확정 | "취소되었습니다" 토스트 알림. 상태가 **취소됨**으로 변경(또는 흐리게 처리). |
| 4 | DB 확인 | `reservations.status`가 'CANCELLED'로 변경됨. `class_sessions.booked_count` 감소함. |

### 시나리오 C: 중복/초과 예약 방지 (엣지 케이스)
**전제 조건**: 잔여석이 1개 남은 회차 찾기.

| 단계 | 액션 | 예상 결과 |
| :--- | :--- | :--- |
| 1 | 사용자 A가 2명 예약 시도 | 에러 "정원 초과" 토스트/메시지. |
| 2 | 사용자 A가 1명 예약 시도 | 성공. |
| 3 | 사용자 B가 1명 예약 시도 | 에러 "매진되었습니다" 표시. |

---

## 4. 테스트 환경 설정
수동 E2E 테스트 전 확인 사항:
1.  `.env.local`에 유효한 Supabase 키 확인.
2.  DB 시딩 완료 확인 (`supabase/seed.sql` 적용).
3.  `NEXT_PUBLIC_URL`이 Auth 리다이렉트용으로 올바르게 설정되었는지 확인.
